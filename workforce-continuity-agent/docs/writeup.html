Workforce Continuity Agent

AI-Powered Automatic Task Reassignment When Employees Are Absent

Team: Ascent Hack

Date: May 2026

Submission: Hackathon Project

Page 1: Problem Statement & Solution Overview

The Problem

When an employee is absent unexpectedly, their pending tasks stall. Managers must manually triage each task: find a replacement, check skills, rebalance workloads. This process is slow, error-prone, and creates bottlenecks that ripple across teams. In fast-moving organizations, even one day of stalled tasks can delay entire project timelines.

Current solutions are reactive and manual. A manager gets notified, opens a spreadsheet, starts calling people. There is no intelligent system that automatically evaluates task complexity, matches skills across the team, and either reassigns tasks to the best available person or completes them autonomously using AI.

Our Solution

The Workforce Continuity Agent is a multi-agent AI system that detects employee absence and automatically handles all pending tasks through a 6-phase pipeline. It analyzes tasks, evaluates team capacity, makes reallocation decisions, and can even complete tasks autonomously using AI code generation and web search.

Key Innovation: The agent doesn't just reassign tasks. It evaluates each task independently and decides whether to reassign it to a human teammate (based on skill matching and workload balancing) or complete it autonomously using AI. This hybrid approach ensures continuity even when the entire team is at capacity.

How It Works — 6-Phase Pipeline

  • Phase 1 — Detection: Absence is detected via webhook (HR system, calendar) or manual trigger. Employee status is updated in the database.
  • Phase 2 — Retrieval: All pending tasks are retrieved from the database. If a GitHub repo is linked, it is cloned into the virtual workspace for context.
  • Phase 3 — Analysis: Each task is analyzed for required skills, complexity, estimated hours, and whether it should be split into subtasks. Uses LLM with heuristic fallback.
  • Phase 4 — Reallocation: The agent evaluates available team members using weighted scoring (skills 50%, workload 30%, availability 20%). Tasks above the confidence threshold are reassigned; others are marked for autonomous completion.
  • Phase 5 — Execution: Tasks marked for autonomous completion are executed by the AI agent. It searches the web for context, generates code using LLM, writes files to the workspace, and pushes to GitHub.
  • Phase 6 — Reporting: A comprehensive manager report is generated with decision rationale, confidence scores, and recommendations.

Page 2: Agent Architecture & Multi-Agent Design

Multi-Agent System

The system uses 5 specialized agents coordinated by a central orchestrator. Each agent has a distinct responsibility and they communicate through a shared activity bus with WebSocket broadcasting.

Orchestrator

The central coordinator that drives the entire 6-phase pipeline. It manages state transitions, broadcasts real-time updates via WebSocket, handles errors gracefully, and ensures each phase completes before moving to the next. It uses asyncio.to_thread() for blocking operations (git clone, LLM calls) to keep the event loop responsive.

Task Analyzer

Uses LLM to analyze each task's requirements: extracts required skills, estimates complexity, determines if the task should be split into subtasks, and classifies the task type (code, research, report, presentation, documentation). Falls back to heuristic analysis when LLM is unavailable.

Availability Agent

Evaluates team members as potential assignees. Calculates skill overlap scores (how well their skills match the task requirements), checks current workload levels, and computes a weighted final score. The scoring formula is: final_score = skill_score * 0.5 + workload_score * 0.3 + availability_score * 0.2.

Reallocation Agent

Makes the critical decision: reassign or auto-complete. For each task, it takes the best matches from the Availability Agent and applies a confidence threshold (0.6). If the best match scores above the threshold, the task is reassigned to that person. If no suitable human match exists, the task is marked for autonomous AI completion.

Executor Agent

The most complex agent. When a task is marked for autonomous completion, the Executor: (1) determines the appropriate folder structure based on task type, (2) searches the web for relevant documentation and context, (3) attempts LLM-powered code generation, (4) falls back to template-based generation if LLM fails, (5) writes files to the workspace, (6) commits and pushes to GitHub. It handles code, documentation, research, reports, and presentation tasks.

Real-Time Communication

All agents broadcast their activities through a shared AgentActivity system connected to WebSocket. The frontend receives live updates showing exactly what each agent is thinking, doing, and deciding. This transparency is crucial for building trust in autonomous systems.

Page 3: Autonomy in Practice & Impact

How Autonomy Works

The system operates on a spectrum of autonomy. Not every task needs AI intervention, and not every task should be reassigned to a human. The agent makes nuanced decisions based on multiple factors:

Decision Flow

For each task, the agent asks: (1) Can a human teammate handle this better? (2) Does the AI have the context and capability to complete it? (3) What's the risk of autonomous completion vs. reassignment delay?

The threshold-based decision engine ensures that tasks are only reassigned when there's high confidence in the match. Low-confidence matches fall back to AI execution, which is always available regardless of team capacity.

Real-World Scenario

Consider a frontend developer (P5) who is suddenly absent. They have 3 pending tasks:

  • Cart System (CODE, 6h): Complex React component. The agent finds P1 (UI Developer, 90% React skill match) as the best human match. Score: 0.78. Above threshold. Reassigned to P1.
  • API Integration (CODE, 4h): Backend work. No frontend developer has strong backend skills. Best match scores 0.35. Below threshold. Auto-completed by agent.
  • Design Review (REVIEW, 2h): Quick review task. P6 (UI/UX Dev) has relevant skills. Score: 0.82. Reassigned to P6.

Verifiable Side Effects

Every action the agent takes produces verifiable artifacts:

  • Database: Task statuses updated, assignments changed, timestamps recorded
  • GitHub: Real commits pushed to real repositories with descriptive messages
  • Notifications: Team members notified of new assignments
  • Reports: Manager reports with full decision rationale
  • WebSocket: Complete activity log of every agent action

Key Takeaways

  1. Hybrid autonomy is practical. Not everything needs AI. The system intelligently decides when to use humans vs. AI based on confidence scoring.
  2. Transparency builds trust. Real-time WebSocket feeds show every decision and reasoning, making the autonomous system auditable.
  3. Graceful degradation. When LLM fails, the system falls back to heuristics. When no human match exists, AI fills the gap. It never stops working.
  4. Real side effects matter. The agent doesn't just plan — it executes. Real git commits, real database updates, real notifications.
Conclusion: The Workforce Continuity Agent demonstrates that multi-agent AI systems can meaningfully reduce organizational friction caused by employee absence. By combining intelligent task analysis, skill-based reallocation, and autonomous execution, it ensures work continues regardless of team disruptions.
